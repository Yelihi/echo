# 초대 AI 운영

`20261002100000_ai_cost_controls.sql` 적용 후 `ai_access_grants`에 등록된 사용자만
유료 음성·문단 제안·새 분석을 요청한다. 등록이 없거나 만료됐거나 DB 검사에 실패하면
AI를 호출하지 않는다. 실제 사용자 ID와 시크릿은 저장소에 기록하지 않는다.
운영자는 Supabase SQL Editor 또는 service-role 관리 경로로 대상 `user_id`와
선택적인 `expires_at`을 등록한다. 애플리케이션은 자기 초대 권한을 만들 수 없다.

- TTS: 사용자별 1분 20회.
- 문단 제안: 사용자별 1시간 5회. 입력 검증을 통과한 요청만 차감한다.
- 분석: 사용자별 24시간 20회, 같은 세션은 최초 포함 최대 3회.
- 허용 후 provider 실패는 한도를 소비한다. 거절되면 provider 호출은 없다.

초대 명단을 준비한 후 worker → migration → 명단 등록 → 앱 순서로 출시한다.
기존 대기 작업의 소유자도 등록해야 한다. 새 worker는 비용 제어 RPC가 없으면
작업을 claim하지 않고 503을 반환한다. migration 전까지 대기열을 보존한다.
자동 출시를 사용할 경우 앱 공개 전에 관리자가 명단을 등록해야 한다.

재시도는 성공한 문장 결과의 `feedback.reuse_key`를 확인한다. 사용자·세션·타깃·
녹음 메타데이터와 실제 오디오 SHA-256·원문 스냅샷·평가 모드·설정 모델·평가 코드
버전이 모두 일치할 때 현재 claim RPC로 복사한다. 키가 없는 과거 결과는 재사용하지 않는다.
프롬프트/스키마/diff 변경 시 worker의 `ANALYSIS_REVISION`을 반드시 올린다.
진행 중인 작업이 끝나기 전에 모델 설정을 바꾸지 않는다.
provider 호출 성공 후 DB 저장 전에 응답이 유실되면 재과금 가능성은 남는다.

한도 이벤트는 운영자가 필요에 따라 30일 이전 행을 정리할 수 있다.
`supabase test db`로 초대·만료·한도·재시도 권한을 검사한다.
애플리케이션 검사는 `npm test -- --runInBand aiAccess reuseKey reuseResult`로 실행한다.
