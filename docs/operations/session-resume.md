# 세션 이탈과 이어하기

- 세션 완료는 모든 필수 녹음 확정과 서버 완료 처리의 성공으로 결정한다. X·뒤로가기·브라우저 종료는 세션 완료나 삭제가 아니다.
- 롤플레잉의 `저장하기`가 성공한 문장은 accepted로 유지된다. 세션 목록과 홈에 저장 문장 수 및 `이어서 연습`을 표시한다. 전체 녹음이 저장되고 완료 처리만 남으면 `완료 확인`을 표시한다.
- 같은 세션 재접속·새로고침 시 스냅샷의 첫 미저장 학습자 문장을 찾아 복원한다. 상대방 음성은 사용자가 `이어서 연습`을 누른 뒤 재생한다. 마지막 상대방 발화가 남은 경우도 재녹음 없이 마무리할 수 있다.
- 녹음 중이거나 저장 전인 경우 X와 브라우저 뒤로가기에 이탈 확인을 표시한다. 저장 요청 중 X는 비활성화하고 뒤로가기는 현재 화면에 유지한다. 새로고침·탭 닫기는 브라우저 기본 경고를 요청한다.
- 프로세스 강제 종료·모바일 브라우저 종료에서는 경고 실행을 보장할 수 없다. 종료 이벤트로 DB 상태를 바꾸지 않고 다음 접속 시 서버의 accepted 녹음을 다시 조회한다. 저장 요청 중 강제 이탈했다면 실제 서버 확정 여부에 따라 복원 위치가 결정된다.
- 현재 롤플레잉의 미저장 오디오는 브라우저 메모리에만 있으므로 이탈 시 복원하지 않는다. DB draft 저장은 별도 연결 과제다.
- 문장 암기는 실제 저장 경로가 아직 연결되지 않았다. 이번 변경은 공통 이탈 안내와 상태 구분만 적용하며, 이어하기 링크를 제공하지 않는다.

## 적용 및 검증

`20260912120000_study_session_resume_history.sql`은 목록 RPC에 연습 중 상태와 저장 문장 수를 추가한다. 새 앱 코드를 실행하기 전에 적용해야 한다. 2026-09-12 연결된 원격 Supabase에 적용했고 로컬·원격 이력 일치를 확인했다.

전체 테스트 321개, 타입 검사, 린트, 프로덕션 빌드를 통과했다. 브라우저 연결이 없어 아래 항목의 실제 브라우저 검증은 남아 있다.

수동 브라우저 확인 항목:

1. 2문장 저장 후 X → 목록의 저장 수 확인 → 이어하기 → 3번째 문장에서 시작.
2. 3번째 문장을 저장하지 않고 뒤로가기 → 취소 시 현재 오디오 유지, 승인 시 이탈 후 3번째부터 복원.
3. 녹음 중 새로고침 → 기본 경고 확인 후 재진입 → 미저장 문장부터 복원.
4. 저장 요청 중 X 비활성화·뒤로가기 차단, 강제 종료 후 서버 확정 결과에 따라 복원.
5. 마지막 문장 저장 후 완료 응답 유실 → `완료 확인`으로 재시도.
6. 마지막 상대방 발화가 있는 세션의 재진입 → 사용자 입력 후 해당 발화 재생.
7. 브라우저 뒤로/앞으로 이동으로 세션을 재방문해도 저장 위치를 다시 조회하며 같은 화면에 갇히지 않음.
